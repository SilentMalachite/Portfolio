PREMISES

Assumptions I design from

I start from the constraints of the workplace and from how people differ.
Instead of building a large system first, I divide the work into pieces that can be continued.

  • Assume interruption

    Work stops in the middle. Decisions and the next step should remain outside a person's memory or a conversation.

  • Handle less at one time

    Reduce the information and the steps, and separate what needs a person's judgment from what a tool can handle.

  • Assume differences in sensing and cognition

    Seeing, hearing, and memory load differ from person to person. Prefer a form that can be used without strain.

  • Prefer what a workplace can sustain

    It can run offline, takes little to introduce and maintain, and does not greatly disrupt the existing flow of work.

  • Try a small part, then check

    Do not aim for a finished form at the start. Build only the part that is needed, try it, and adjust.

INTERRUPTIBLE / RESUMABLE
SoujoWork you can pick up again. 01 / RESUMABLE WORK
Work design / AI developmentPublic source

Pick up where you left off.

Soujo (層序)

  • Cognitive load
  • AI development
Problem
Every interruption can mean reconstructing decisions and next steps. Depending on human working memory or an AI conversation history makes resuming and handing over work harder.
Approach
Move the state outside people’s heads and conversations, and keep each task small. Interruption and resumption are part of the design, with the aim of reducing memory demands.
Design
Four files hold the specification, plan, log, and next step. Work proceeds in small “layers,” and Claude Code and Codex can share the same records.
Result & status
A CLI and shared skills for Interruptible / Resumable AI Development, with public source. Effects on cognitive load and efficiency have not been measured.
Tech
TypeScript / CLI / Markdown

AlchemIIIF

  • Welfare
  • Cultural heritage

Problem
Publishing archaeological reports involves image processing, metadata, and review. The project aims to connect cultural heritage publishing with meaningful tasks in Japan’s welfare employment support services.
Approach
I draw on my expertise in archaeology to break the work into manageable tasks, separating understanding the material from processing, data entry, and review.

PDF conversion, image cropping, metadata entry, approval, and publication form one workflow. IIIF provides a shared format for publishing and viewing the material.

PDF TO IMAGES UtsushiFrom PDF pages to images. 03 / DOCUMENT CONVERSION
PDF conversion / Windows appDownload available

Turn page-by-page export into one workflow.

Utsushi.Win

  • Structuring work
Problem
Preparing images from multiple PDFs means repeatedly choosing pages, resolution, and filenames, then checking which pages failed.
Approach
Group repeated choices and show what will be produced before conversion. Support both interactive use and automation of routine tasks.
Design
Select PDFs or a folder, set page ranges, resolution, and naming, and preview output size and filenames. Review failures by page afterward, using either the GUI or CLI.
Result & status
A Windows app that produces a PNG or JPEG for each page, distributed as a ZIP with no installer required. Password-protected PDFs are supported through the CLI, not the GUI.
Tech
C++ / WinUI 3 / Windows.Data.Pdf

BREAK REMINDERS HitoikiA moment to step away. 04 / TAKING A BREAK
Break reminders / macOS & WindowsDownload available

Build a cue to take a break into the screen.

Hitoiki

  • Breaks and work support
Problem
When absorbed in a task, it is easy to miss a break. A cue is needed to notice the time and pause the work.
Approach
Let a schedule and a screen prompt carry the task of remembering a break. At set intervals or clock times, a break view appears on every display to create a pause in the work.
Design
After a few flashes, a dark overlay and countdown cover every display. Schedules falling in the same minute are merged, and holding Esc for three seconds ends a break early. Settings stay on the device; the app makes no network requests.
Result & status
Downloads are available for macOS (Apple silicon) and Windows. First launch requires OS confirmation. The app is a reminder rather than a complete input lock; detailed settings are edited in a JSON file.
Tech
TypeScript / Electron

MY APPROACH

Start with people.
Respond with technology.

Keep learning and checking,
even after building.

01

Start with people.

Before choosing technology, I ask who is struggling, where, and why, including the people supporting the work and its environment. My writing in A11yLab follows the same approach.

02

Break complexity down.

Divide a large problem into parts people can handle one at a time. The workflow in AlchemIIIF and the “layers” in Soujo make steps and responsibilities visible.

03

Turn differences into design.

Instead of expecting people to endure a difficulty, change the conditions that create it. Soujo records the next step so work can resume without relying on memory.

04

Build small and check.

Start with a small trial and develop what is needed. I define the problem and criteria, use AI agents in the development process, and check the results and limitations.
