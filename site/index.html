PREMISES

設計するときの前提

現場の制約や、人の特性から考えています。
大きなシステムを最初から作るのではなく、続けられる単位に分けます。

  • 中断を前提にする

    作業は途中で止まる。決めたことや次の一手を、人の記憶や会話の外に残せるようにする。

  • 一度に扱う量を小さくする

    情報量や手順を減らし、判断が必要なところと、道具に任せられるところを分ける。

  • 感覚や認知の違いを前提にする

    見え方、聞こえ方、記憶負荷の違いは個人差がある。無理なく扱える形を優先する。

  • 現場で続けられることを優先する

    オフラインでも動く、導入や保守の負担が小さい、既存の仕事の流れを大きく崩さない。

  • 小さく試して確認する

    最初から完成形を目指さず、必要な部分だけを作り、使ってみて調整する。

  • 業務整理
課題 / Problem
複数のPDFからページごとの画像を用意するとき、対象ページ、解像度、保存名を繰り返し決め、変換できなかったページも確認する必要があります。
考え方 / Approach

PDFやフォルダをまとめて選び、ページ範囲・解像度・命名を設定。出力サイズと名前を事前表示し、変換後はページ単位で失敗の理由を確認できます。GUIとCLIを用意しています。

ページごとのPNG・JPEGをつくるWindowsアプリを、インストール不要のZIPで配布。日常の定型作業は迷わないGUIで、パスワード付きPDFなどの高度な一括処理はCLIで役割分担する設計です。

休憩支援 / macOS・Windows配布版あり

休憩のきっかけを、画面の中につくる。

Hitoiki（一息）

  • 休憩・作業支援
課題 / Problem
作業に没頭していると、休憩のタイミングを逃してしまう。時間に気づき、いったん手を止めるきっかけが必要です。
考え方 / Approach
休憩を思い出す負担を、時間と画面の仕組みに任せる。決めた間隔や時刻に全モニターへ休憩画面を出し、作業に区切りをつくります。
設計 / Design
画面を数回点滅させた後、暗い表示と残り時間で全モニターを覆います。同じ分に重なる予定は一つにまとめ、Escの3秒長押しで途中解除できます。設定は端末内に保存し、通信は行いません。
成果物・現状 / Result
macOS（Apple silicon）・Windows向けの配布版を公開。初回起動にはOSの確認が必要です。緊急時の操作を妨げない安全な設計とし、設定は外部ファイルでシンプルに管理できます。

ABOUT

異なる現場を、
一つの設計につなぐ。

SilentMalachite
考古学・教育・福祉・医療から、
ソフトウェアとAIの活用へ。

考古学、高校教育、障害福祉、医療、就労支援。異なる現場を経験するなかで、技術だけでは問題が解決しないことを学んできました。仕事の手順、情報の伝わり方、使う人の負担まで含めて考える必要があります。

いまは、現場の仕事を理解し、必要な部分だけを技術へ置き換えることに取り組んでいます。ソフトウェア開発やAIエージェントの活用も、そのための手段です。課題を整理し、小さくつくり、人が続けられる形を考えています。
