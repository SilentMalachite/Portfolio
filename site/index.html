Soujo（層序）

課題 / Problem
開発を中断するたびに、決めたことや次の作業を思い出す。人の作業記憶やAIの会話履歴に頼るほど、再開や引き継ぎが難しくなります。
考え方 / Approach
状態を人の頭や会話の外に置き、一度に扱う作業を小さくする。中断と再開を前提に、記憶負荷を下げる設計を考えました。
設計 / Design
仕様・計画・記録・次の一手を4つのファイルへ。小さな「層」ごとに進め、Claude CodeとCodexの間でも同じ記録を引き継げます。
成果物・現状 / Result
Interruptible / Resumable AI Developmentを支えるCLIと共通スキルを公開。認知負荷や作業効率の改善効果は未測定です。

ページごとの画像化を、一つの手順に。

Utsushi.Win

課題 / Problem
複数のPDFからページごとの画像を用意するとき、対象ページ、解像度、保存名を繰り返し決め、変換できなかったページも確認する必要があります。
考え方 / Approach
繰り返す指定をまとめ、出力の見通しを先につける。手元での操作と、定型作業の自動処理の両方から使える形にしました。
設計 / Design
PDFやフォルダをまとめて選び、ページ範囲・解像度・命名を設定。出力サイズと名前を事前表示し、変換後はページ単位で失敗の理由を確認できます。GUIとCLIを用意しています。
成果物・現状 / Result
ページごとのPNG・JPEGをつくるWindowsアプリを、インストール不要のZIPで配布。パスワード付きPDFはCLIで扱い、GUIは非対応です。

BREAK REMINDERS Hitoiki一息つく、きっかけを。 04 / TAKING A BREAK
休憩支援 / macOS・Windows配布版あり

休憩のきっかけを、画面の中につくる。

Hitoiki（一息）

課題 / Problem
作業に没頭していると、休憩のタイミングを逃してしまう。時間に気づき、いったん手を止めるきっかけが必要です。
考え方 / Approach
休憩を思い出す負担を、時間と画面の仕組みに任せる。決めた間隔や時刻に全モニターへ休憩画面を出し、作業に区切りをつくります。
設計 / Design
画面を数回点滅させた後、暗い表示と残り時間で全モニターを覆います。同じ分に重なる予定は一つにまとめ、Escの3秒長押しで途中解除できます。設定は端末内に保存し、通信は行いません。
成果物・現状 / Result
macOS（Apple silicon）・Windows向けの配布版を公開。初回起動にはOSの確認が必要です。操作を完全に遮断するロックではなく、細かな設定はJSONファイルで行います。
利用技術 / Tech
TypeScript / Electron

MY APPROACH

人から考え、
技術で応える。

つくって終わりにせず、
理解と検証を重ねていく。

01

人から考える。

技術を選ぶ前に、誰が、どこで、何に困っているか。使う人だけでなく、その仕事を支える人や環境から考えます。A11yLabの発信も、その観察の延長にあります。

02

複雑さを分解する。

大きな問題を、一つずつ扱える単位へ。AlchemIIIFの工程やSoujoの「層」のように、手順と役割を分けて見通しをつくります。

03

特性を設計に変える。

「苦手だから我慢する」のではなく、苦手が起きにくい仕組みを考える。Soujoでは次の一手を記録に残し、記憶に頼らず再開できる形にしています。

04

小さく作って検証する。

最初から大きなシステムを作らず、小さく試して必要なものを育てる。人が課題と判断基準を定め、AIエージェントも活用しながら制作し、結果と制限を確認します。

ABOUT

異なる現場を、
一つの設計につなぐ。

SilentMalachite
考古学・教育・福祉・医療から、
ソフトウェアとAIの活用へ。

考古学、高校教育、障害福祉、医療、就労支援。異なる現場を経験するなかで、技術だけでは問題が解決しないことを学んできました。仕事の手順、情報の伝わり方、使う人の負担まで含めて考える必要があります。

いまは、現場の仕事を理解し、必要な部分だけを技術へ置き換えることに取り組んでいます。ソフトウェア開発やAIエージェントの活用も、そのための手段です。課題を整理し、小さくつくり、人が続けられる形を考えています。
